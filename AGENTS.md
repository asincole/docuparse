# AGENTS.md

## Commands

Task runner is **mise** (`mise.toml`). Use these instead of raw cargo:

```
mise run fmt          # format (nightly rustfmt)
mise run fmt-check    # CI format check
mise run lint         # cargo clippy -- -D warnings
mise run test         # nextest (all features) + doctests (nightly)
mise run test-doc     # doctests only
mise run docs         # build docs locally (nightly, all features)
mise run coverage     # cargo llvm-cov nextest --html
mise run bootstrap    # machine setup: pinned pdfium lib + OCR models
mise run build-cli    # release CLI with OCR (+ hotpath) features
```

**Order:** `fmt-check -> lint -> test` (matches CI).

### Focused test runs

```bash
cargo nextest run --all-features <filter>       # single test / pattern
cargo nextest run --features ocr-onnx           # only OCR tests
cargo test --doc --all-features                 # doctests only
```

## Environment

- **Rust edition 2024**, stable toolchain, nightly used for fmt/docs/coverage
- **`PDFIUM_LIB_PATH`** must point to the pdfium shared lib dir. Set in `mise.local.toml` (gitignored).
- **`PDFIUM_LIB_PATH='./pdfium-lib'`** is the local convention; `pdfium-lib/` is gitignored.
- OCR env vars (`OCR_DET_MODEL_PATH`, `OCR_REC_MODEL_PATH`, `OCR_DICT_PATH`) are in `mise.local.toml` — only needed for ONNX integration tests.

## Architecture

Cargo workspace: the `docuparse` library plus the `docuparse-cli` binary crate in `crates/docuparse-cli`. The lib is built on `pdfium-render` (Pdfium C++ bindings); `src/lib.rs` is its root.

```
src/
  lib.rs             - re-exports, feature gating
  pdf_document.rs    - PdfDocument: load, text extraction, rendering, OCR orchestration
  pdfium_singleton.rs - lazy pdfium init (once_cell)
  text.rs            - native text layer extraction
  render.rs          - page rendering via pdfium
  validation.rs      - PDF magic bytes, size guards, path checks
  metadata.rs        - document metadata
  open_config.rs     - PdfOpenConfig (builder pattern via `bon`)
  utils.rs / utils/  - shared utilities (contains_real_words, constants)
  ocr.rs             - OcrError enum, OCR module re-exports
  ocr/               - feature-gated OCR subsystem
    backend.rs       - OcrBackend trait, OcrConfig, OcrPageResult
    onnx_backend.rs  - OnnxOcrBackend (feature: ocr-onnx, uses oar-ocr crate)
    llama_backend.rs - LlamaServerBackend (feature: ocr-openai, HTTP vision API)
    document.rs      - per-page OCR orchestration on PdfDocument
```

## Feature flags

```
default      = []                                   # core PDF only
ocr          = []                                   # shared OCR trait/types
ocr-onnx     = [ocr] + oar-ocr                     # local ONNX inference
ocr-openai   = [ocr] + reqwest,base64,serde,turbojpeg  # HTTP vision API
parallel     = rayon                               # parallel OCR across rayon thread pool
hotpath      = hotpath/hotpath                     # per-function profiling
hotpath-alloc = hotpath/hotpath-alloc + hotpath    # allocation profiling
```

All features are tested together: `--all-features`.

## Testing notes

- Test framework: **nextest** (not plain `cargo test` for unit/integration).
- Parameterized tests use **rstest** (`#[rstest]`).
- Integration test `tests/onnx_integration.rs` requires `--features ocr-onnx`. The main test is `#[ignore]` — run with `--run-ignored only`.
- Fixture PDFs are generated by `cargo run --example generate_fixtures` into `examples/fixtures/` (gitignored). Not needed for unit tests.
- `tests/fixtures/known_text.png` is committed for the ONNX image test.
- Dev profile uses `opt-level = 1` with dependencies at `opt-level = 3` — don't be surprised by non-zero optimization.

## Code style

- `rustfmt.toml`: `imports_granularity = "Crate"`, `group_imports = "StdExternalCrate"`, `unstable_features = true` (requires nightly rustfmt).
- Builder pattern via the `bon` crate throughout (e.g. `PdfOpenConfig::builder().build()`).
- Error types use `thiserror` with named fields.
- No comments in code unless explicitly asked.

## CI

GitHub Actions (`ci.yml`): fmt-check → clippy → test (all features). Also a separate docs build job using nightly.

Release automation via `release-plz` on push to `master`.
